# NVFP4 / GDN 实验结果（2026-10-10）

**本轮没有确认稳定的端到端提速。** 部分 NVFP4 矩阵更快，但长 Prefill 没有获益；非 CP GDN 融合在本机回退；跨 lane 投影打包也没有在真实历史请求中确认收益。全负载动态投影优化尚未完成，不能写成所有优化已经做完。

这次提交发布测试结果，不更换本分支的引擎代码。以下报告比较多个独立实验构筑，不能把 `feature/kvmem` 当前源码当成每个实验臂的源码。原始请求、图片、生成正文、SSE 和资源采集文件保留在本地，不上传；公开的是方法、汇总、负结果和验收边界。

## 结果速览

| 改动 | 算子结果 | 完整请求结果 | 处理 |
|---|---|---|---|
| NVFP4 形状调度 | 513–1023 token 的 residual 投影耗时减少约 15–27% | 48K 单路 TTFT +0.07%，双路 −0.06%；长输入实际未进入新调度区间 | 仅证明这些形状的组件收益 |
| 非 CP GDN 融合 | T1024 耗时 +21.05% | 48K 单路 TTFT +2.15%、整请求 +2.92%；双路 TTFT +0.22% | 默认关闭，没有已验证的正收益条件；不承诺与旧输出逐 bit 一致 |
| 两项组合 | NVFP4 部分组件收益保留，GDN 仍回退 | 48K 单路 TTFT +0.57%、双路 −0.14% | 未确认稳定整体收益 |
| 后续跨 lane NVFP4 打包 | 时间线中 gate/up 少约 59ms，down 多约 98ms、down 量化多约 12ms | 最新历史请求 ABBA：两组实际打包的冷 Prefill GPU 耗时 +0.83% / +0.79%，TTFT +1.31% / +0.21% | 已编入日常构筑，但开关默认关闭、当前关闭 |
| NVFP4 残差舍入实验 | 独立 oracle 通过；消除已构造的宽度舍入差异 | 旧/新生成有差异，chunk128 数学案例出现可重复截断反例 | 留在独立实验，未装入日常服务，不记作提速 |

## 真实请求回归与限制

最新四臂 OFF/ON/ON/OFF 共 32 批、64 请求：56 正常完成，8 按事先设定的 60 秒期限取消；57 个完整工具调用的名字和参数均通过原始 JSON Schema，没有流错误。没有执行外部工具，也没有把未完成的长答案当作质量通过。请求原本不带 seed，服务会为每次请求生成随机 seed，整批输出长度和耗时因此不能充当逐 token 质量证明或单项优化归因。

热缓存对照多数不执行打包；缓存命中的收益应归于少算前缀，不能归于未执行的打包。打包时每请求记录的共同墙钟不能相加作为 GPU 时间，应使用按 token 分摊的工作时间或整批时间线。

资源保护从 12GiB commit 余量硬停止改为 12GiB 预警 / 8GiB 硬停止后，原完整计划得以完成；最低余量 9.006GiB、物理可用 21.739GiB、显存空闲 2676MiB、WSL swap 为零。这证明旧线在此负载下过于保守，不证明两个满 256K 历史的峰值容量已验收。

早期大模型多遍 Nsight 采集发生停滞，随后观察到 WSL 非干净重启，原因尚未确认，不能归因为已证引擎 OOM。后续小组件先核对 pass 数、再执行单遍真实采样，未重复该现象。真实 down 样本读量减少约 40%，但时钟也变化，尚不足以唯一解释完整时间线的回退。

日常保持 2 lane、每路 36K GPU 窗口 / 256K 逻辑上下文、FP8、DFlash2 K7、Vision、原生前缀缓存；HiCache、非 CP GDN 融合、跨 lane 打包及舍入实验关闭。报告不承诺整机吞吐提升、所有输出无损或正式语义质量验收完成。
