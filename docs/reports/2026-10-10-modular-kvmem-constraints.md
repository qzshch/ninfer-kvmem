# 模块化、上游吸收与验证记录（2026-10-10）

本轮完成了 KVMem 策略层拆分、适用的上游机制适配，以及 NInfer 结构化输出和工具约束接入。日常构筑已使用新代码，仍为 **2 lane × 36,864 驻留窗口、每路 262,144 逻辑上下文、FP8、DFlash2 K7、Vision、Native 前缀缓存、18 GiB pageable Host**。HiCache、非 CP GDN recurrence 融合、跨 lane 投影打包和数值舍入实验继续默认关闭。

| 用户目标 | 已完成内容 | 边界 |
|---|---|---|
| 降低耦合 | 检索、打分、语义保留、窗口及容量算法移入独立 `kvmem_core`；通过明确的 NInfer adapter 连接配额、媒体与错误类型 | 源码模块化；不是动态插件 ABI。GPU 页表、StateImages、Graph 和 Native checkpoint 仍属于后端 |
| GDN 输出归一化与 gating | 核对生产 `text.cpp` 的 `ops::gated_rmsnorm`，通过独立数值参考测试 | 原构筑已经融合；不重复引入、不宣称本轮产生新的 GDN 提速。它不同于默认关闭的 recurrence 实验 |
| 视频 | 保留原生视频解码；加入有限正 FPS 验证及浮点 frame count 的安全收窄 | 四帧合成 AVI 已在全参数构筑中实际推理；不代表长视频容量或质量验收 |
| Responses 指令 | `instructions` 与晚期 System/Developer 都保留，非文本 developer 输入明确拒绝 | 沿用 Native 角色顺序；没有照搬 llama.cpp 的单 system 合并重排 |
| 会话生命周期 | 共享前缀 lease、取消、暂停、恢复、删除父响应后子响应续接、资源归还已验证 | Native 没有 llama.cpp 的磁盘会话目录，不另建重复 GC/资源账本 |
| 结构化输出、工具约束 | 分提交吸收 XGrammar、GBNF、JSON mode、支持的 JSON Schema 子集、choice/regex、组合及诊断、tuple/数值界限、工具选择和严格参数约束 | 不支持的 Schema 会明确报错；约束不等于答案语义正确 |

结构与后续更新方法见 [后端集成契约](../maintainer/backend-integration.md)，固定来源见 [版本清单](../../backends/versions.json)。本轮复核的 NInfer 为 `81c8ce09`，KVMem master 为 `d9ae944b`、多后端分支为 `ae48ec00`。仅吸收清单中的七项 NInfer 约束依赖提交，没有混入无关 BF16/Q8 调参或替换成拒绝 DFlash/视频的官方 NInfer adapter。

测试发现并修复了一处 MTP/KVMem 生命周期问题：第一次冷 prefill 的检索 placement 把尚未提交的 lookahead 页迁到 Host。诊断中该页 `columns=0, references=1, writers=1, pins=0, host=1, device=0`；执行单元收尾无法退还它，触发保护页异常。现在未提交增长页保留在 Device，正常收尾再退还；已提交历史选页和 checkpoint 保护不变。对应独立提交为 `897fe116`，包含真实双 lane 跨窗口回归。

性能对照使用冻结日常二进制与候选，按 **A→B→B→A** 启动四次；同权重、同参数、同公开输入与 seed，每请求实际发布 256 token。长输入约 54.6K，确实跨过 36K 窗口。下表是两次重复的范围，单位为**输出 tok/s，包含 prefill、排队和缓存搬运**；双请求只用一次整批 wall time 作分母，不相加重复计算的每请求耗时。这里的“单请求”仍使用配置为两槽的服务。

| 负载 | 基线冷 | 候选冷 | 基线热 | 候选热 |
|---|---:|---:|---:|---:|
| 短单请求 | 159.1–167.2 | 160.6–167.2 | 72.5–133.2 | 133.2–141.3 |
| 短双请求 | 201.0–214.1 | 203.5–212.8 | 138.3–268.6 | 260.0–275.3 |
| 长单请求 | 23.4–24.1 | 24.0–24.7 | 48.0–72.8 | 66.1–70.6 |
| 长双请求 | 17.2–19.9 | 24.0–24.4 | 83.4–103.1 | 102.4–105.0 |

冷短吞吐和冷长单请求基本重合；本轮长双请求记录更好，但没有做模块逐项消融，热缓存又有明显重复波动，不能把百分比归功某个内核。短双请求的冷阶段也复用了 29 token 的公共前缀，并非严格零命中冷态。表中的热态长输入复用约 54,624 token。

四类单请求的所有重复及跨版本生成 token IDs 一致。双请求在**基线自己的重复**中也有差异，候选短双请求的重复也不同，因此本轮不承诺动态并发的逐 token 一致，不把格式、数值 Op 或冒烟通过解释为正式语义质量等价。后续诊断需要把每 token 所属 batch profile/验证宽度与固定调度重放关联，区分原有批次数值变化和新增行为。完整两路 256K 实体历史峰值、多轮语义质量和 DFlash1/DSpark 不在本轮真实模型资格范围内。

所有失败均保留：MTP 页生命周期失败已复现并修复；视觉 fixture 曾误传字符串布尔参数，修正后通过；一次启动前安全门因旧模型内存尚未回收而拒绝，没有运行该用例。JSONL 文件测试在 C 盘写满时连续 5/5 失败，在 WSL 原生临时目录 5/5 通过；归档、校验并清理自有旧 CUDA 临时生成物后，原 C 盘目录 5/5 通过。构建临时目录已放 G 盘，测试临时目录使用 WSL 原生目录；没有通过改生产日志实现掩盖磁盘问题。
